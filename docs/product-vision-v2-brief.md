# AI Reading Companion · 产品愿景 v2 简报

> 记录：2026-09-03，用户口述的产品思考。双重用途：①新对话优化该项目的启动文档；②AI PM 面试中"展示 Agent 思考"的素材源。

## 一、用户的产品判断（原意保留）

1. **去 Obsidian 化**：做成独立 APP，不依赖 Obsidian 作为载体。
2. **学习观**：学习中"提问"是核心动作，独立输出笔记是另一核心动作。AI 的作用收窄为两件事：**回答**与**纠错**。
3. **Memory 的场景化思考**：不同场景、不同人需要的 Memory 不一样。学习场景的 Memory = 我已掌握的知识 + 我未掌握的知识；**未掌握的知识就藏在我提出的问题里**。学习要靠 Memory 先建立框架；Memory 的作用是回答"这个问题处于框架的什么位置、关联点有什么"——图谱式定位，而不是全量细节复述。
4. **Agent 自学习 = 逐渐了解用户**：以问答为例，Agent 应学习用户期望的回答形式、深度、侧重的细节等偏好。

用户自评：当前项目距理想状态还有差距；希望把它**作为一个独立的产品设计来展现自己对 Agent 的思考**。

素材已补齐：用户与 ChatGPT 的深度讨论（https://chatgpt.com/share/6a9be62a-f2bc-83e9-a940-cbe9b9f3b2d9 ），全文与摘要见同目录 [chatgpt-discussion-learning-protocol.md](chatgpt-discussion-learning-protocol.md)。核心：一套"课程模式"教学协议——先对象后分类、纵向深挖不横向铺开、难度闸门、连续建模；并含 Project Memory vs Project Instructions 的偏好固化讨论。

## 二、与现状的差距（新对话的切入点）

现有实现（v0.x，见 README/agent-technical-design.md）已有的"种子"：

- 候选式学习偏好记忆：重复且明确的偏好才进入可审阅记忆，确认后才生效 → 是"自学习=了解用户"的雏形，但只覆盖**回答风格**，不覆盖**知识状态**（已掌握/未掌握）。
- Context Receipt / 工具预算 / 证据车道 → 可控 AI 的基础设施，可复用。
- 本地检索 lane、来源回链 → 与"图谱式定位"所需的结构化知识层天然衔接。

差距（v2 需要设计的）：

1. **学习者模型缺失**：没有"已掌握/未掌握"的知识状态表示；问题（提问记录）未被当作"未掌握知识"的信号源。
2. **框架/图谱层缺失**：能做文件夹级检索，但没有知识框架（Module/Relation）来定位"这个问题在框架中的位置与关联"。注意：用户的"知识持续集成系统"（Registry/Fragment/Claim/Relation，见 chat-archive 项目线程）正好是现成的框架层候选，两个项目有合并叙事的空间。
3. **载体迁移**：Obsidian 插件 → 独立 App 的架构路径未定义（本地优先、数据可携、保留 Obsidian 作为可选前端？）。
4. **纠错闭环缺失**：AI 的"纠错"作用（对用户独立输出笔记的反馈）没有任何设计。

## 三、新对话 kickoff 建议问题清单

1. 学习者模型怎么建模最小可用？"未掌握知识"从提问中提取的信号可靠吗？要不要用户确认？
2. 框架层用轻量图谱（Module/Claim/Relation 沿用知识系统集成设计）还是自由标签？冷启动怎么办（框架初始从哪来）？
3. 独立 App 的形态：本地优先桌面端？Obsidian 还能作为数据源之一吗？
4. 纠错功能的产品边界：AI 纠错的是"事实错误"还是"理解偏差"？误纠错如何防？
5. 偏好自学习的边界：沿用候选式确认机制，还是允许更强的自动适应？

## 四、面试叙事价值（写简历/面试时用）

- 一句话定位：不满足于"做一个 Obsidian 插件"，而是把"AI 如何辅助学习"抽象为产品论题：**AI 只做回答与纠错，知识消化必须由人完成；Memory 按场景建模——学习场景的 Memory 是掌握状态与框架位置，不是聊天记录**。
- 高频面试题的现成答案：
  - "Agent Memory 怎么设计？" → 场景化 Memory + 未掌握知识藏在提问里 + 框架定位（图谱式）。
  - "Agent 自学习是不是伪需求？" → 候选式偏好记忆（重复信号→可审阅→确认生效），自学习=逐渐了解用户，但要可审计可撤销。
  - "RAG/知识库产品和图谱怎么选？" → 检索 Chunk ≠ 知识 Fragment（来自 chat-archive 项目的设计决策），框架定位与全量细节是两层。
