# AI Reading Companion：插件重构与独立 App 开发计划

状态：执行中  
开始日期：2026-08-20  
原则：严格按阶段推进；上一阶段通过自动测试与人工验收后，下一阶段才进入实现。

## 总目标

把现有 Obsidian 插件逐步演进为“本地优先的文档理解与层级提问工作台”，同时保留 Obsidian 宿主，并让独立桌面 App 复用同一套领域模型和 Agent Runtime。

核心用户链路保持不变：

```text
原文 → 问题 → 回答 → 选中片段 → 待问问题或可编辑摘录
```

关系图只记录用户真实创建的连接，不把模型推断自动写成知识关系。

## 阶段 1：四个 P0 阻断问题

### 1.1 URL 抓取安全

- FetchURL 只接受本轮可信搜索结果中登记过的 URL；
- 只允许 `https`，拒绝 userinfo、非常规端口、环回、私网、链路本地和云元数据目标；
- 只有宿主能够校验 DNS 与每一跳重定向时才允许客户端直抓；当前 Obsidian 宿主无法提供这些信息，因此默认关闭客户端直抓，仅允许受支持服务商的托管抓取；
- 限制响应字节、内容类型和超时；
- 诊断只记录错误类别和次数，不记录 URL、查询或正文。

验收：恶意直连、编码地址、IPv4/IPv6 私网、可信域跳转到私网和未登记 URL 均被拒绝；正常搜索结果仍可抓取。

### 1.2 分支上下文隔离

- 以当前分支端点为起点，沿 `parentQuestionMessageId` / `parentAssistantMessageId` 回溯祖先链；
- 只把祖先问题—回答对交给 Context Builder；
- 当前查看节点与继续提问端点分离；
- 兄弟分支只有用户显式选择后才可作为摘要证据加入。

验收：A/B 两个兄弟分支互不进入对方模型请求；页面跳转不会改变继续提问的分支端点。

### 1.3 会话体积淘汰

- 超限时先移除 DOM、运行态、重复来源、大字段和可重新生成内容；
- 再裁剪最旧回答正文，但保留消息 ID、父子关系和摘要；
- 永远优先保留活动会话、待问清单、可编辑摘录草稿和当前路径；
- 无法完整保存时返回显式降级报告，并在 UI 提示；不得静默保存空会话列表。

验收：单个超大活动会话重载后仍存在，待问与未保存摘录可恢复；用户能看到发生过裁剪。

### 1.4 工具证据总预算

- RunPlan 为整轮运行冻结共享工具证据字符预算；
- Tool Gateway 在所有工具、所有轮次和复杂问题子任务之间共享同一预算；
- 单工具结果先受权限预算限制，再受共享证据预算限制；
- 预算耗尽后撤下工具，模型用已有材料完成回答；
- 记录结果字符数、截断次数和预算拒绝次数，不记录查询正文或工具结果。

验收：多个工具累计结果不超过 RunPlan 上限；复杂问题拆分不能重置预算；预算耗尽不会让整轮回答失败。

## 阶段 2：共享领域、Agent 用例与平台接口

目标目录：

```text
packages/
  domain/       # Document、Block、Anchor、Question、Answer、Excerpt、Session
  agent-core/   # AskQuestionUseCase、Runtime、Plan、Context、ToolGateway
  storage/      # Session/Project/Excerpt repository 接口与序列化
  platform/     # HttpClient、SecretStore、FileAccessPolicy、Clock
apps/
  obsidian/     # Vault、Workspace、SecretStorage、Notice 适配
```

首轮从 `main.ts` 抽出：

1. `ConversationGraph`：消息与问题树的纯状态转换；
2. `AskQuestionUseCase`：构建 RunPlan、Context、Runtime 并返回结果；
3. `SessionRepository` 与容量策略；
4. `HttpClient`、`SecretStore`、`DocumentRepository`、`FileAccessPolicy`；
5. View 只订阅状态并发出命令，不再直接拼装模型上下文。

验收：领域和 Agent 核心无 `obsidian` import；关键状态转换有独立单元测试；逐步开启 TypeScript 严格检查。

## 阶段 3：现有插件页面重构

桌面页面固定为三层：

1. 文档与对话抽屉：搜索和切换，不永久占据顶部高度；
2. 左侧知识控制台：问题树、待问、可编辑摘录、折叠原文，整栏只有一条滚动；
3. 右侧回答阅读区：正文最大宽度 720–820 px，输入区固定底部。

交互规则：

- 问题树点击只导航；“从这里继续”才改变分支端点；
- 待问卡片默认两行摘要，一个主操作，其余动作放更多菜单；
- 摘录保留编辑框并自动保存草稿；
- 选中文字后只显示“问这段”和“加入摘录”；
- 左栏可拖动并可恢复默认宽度；
- 不允许模块内部出现额外滚动区域。

验收：长会话、20 个待问、10 个会话、窄窗口、150% 缩放和键盘导航均可用；切换节点不丢滚动、选区或草稿。

## 阶段 4：独立 App Markdown Alpha

默认技术路径：先用 Electron + React/TypeScript 验证；共享核心不依赖 Electron，保留后续评估 Tauri 的可能。

Alpha 范围：

- 创建本地项目；
- 导入单个或文件夹内的 `.md`；
- 解析标题、段落、列表、代码、表格、图片和源位置；
- 阅读、提问、创建子问题、管理待问、编辑摘录；
- SQLite 保存项目、会话、问题树、草稿和摘录；
- 项目/文件夹范围内的词法全文检索；
- 系统密钥存储与最小文件访问权限；
- 将确认内容导出为 Markdown。

非目标：云同步、多人协作、全库向量化、自动知识图谱、移动端。

## 阶段 5：`.docx`、图片与文档重新锚定

- 只承诺 `.docx`，不承诺旧 `.doc`、宏文档和像素级版式还原；
- `.docx` 先转安全的语义 HTML，再进入统一 Block 模型；
- 抽取并本地化图片，限制 ZIP 展开体积、单图/总图大小和外部资源；
- 原始文件保持只读，记录导入版本和内容哈希；
- 锚点由 `blockId + offset + exactQuote + documentVersion` 组成；
- 文档更新后按稳定块、上下文窗口和 exact quote 重新锚定；失败项进入待修复队列。

验收：常见标题、列表、表格、脚注、链接和图片可导入；恶意/超大文件安全失败；原文修改后多数已有问题仍能定位。

## 阶段 6：分支概览、回答目录与次级问题图谱

- 回答目录来自当前回答真实标题，只承担阅读导航；
- 分支概览来自问题父子关系，显示未问、已问、已解决和暂放状态；
- 图谱只显示用户建立的来源引用、片段派生问题和确认摘录；
- 点击节点定位对应原文、问题、回答或摘录；
- 图谱是次级视图，不替代主要阅读区，不自动制造概念边。

验收：任一图谱边都能解释其用户行为来源；删除/移动节点不会破坏原始对话；大树支持折叠和按路径聚焦。

## 全阶段质量门槛

- 每次提交通过 TypeScript、ESLint、release check、smoke tests；
- 关键 UI 回归加入自动门禁，不允许验收脚本与真实工具名称漂移；
- 任何持久化格式变化都包含向后迁移与损坏数据隔离；
- 安全与权限拒绝不得自动重试；
- 运行诊断不得记录原文、问题正文、URL、路径、回答或 API Key；
- 每阶段记录构建产物大小、长会话渲染耗时和模型调用次数变化。
