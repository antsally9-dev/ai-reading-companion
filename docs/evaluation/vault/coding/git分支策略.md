# Git 分支策略

## rebase 与 merge

merge 保留真实历史，把两条分支的末端合并成一个提交节点，历史上能看出并行开发过程，但多次合并会让历史图显得杂乱。rebase 把分支上的提交逐个搬到目标分支最新提交之后，历史呈一条直线，看起来更整洁，但会改写提交哈希。

团队协作的分支上避免 rebase 已经 push 出去的提交，否则队友同步时需要处理重复的提交。个人本地分支在合并前 rebase 到最新主分支是安全且推荐的做法。

## 提交规范

每个提交只做一件事，提交信息第一行用祈使句概括改动，正文解释为什么改而不是改了什么。
